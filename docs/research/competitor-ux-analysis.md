# 竞品 UX/功能深度调研

> 调研时间：2026-07-16
> 目的：分析主流旅行产品的用户使用方式、产品设计逻辑和亮点功能，为 HearHere 提供设计参考
> 关注重点：兴趣浏览、推荐分类系统、AI 交互模式

---

## 一、TripAdvisor（全球最大旅行平台）

### 1.1 首页"按兴趣探索"模块

TripAdvisor 首页有一个核心的推荐入口——**"按兴趣查找景点玩乐"**：

```
┌────────────────────────────────────────────┐
│  你在寻找什么类型的体验？                      │
│                                            │
│  🏔️ 户外活动    🍽️ 美食之旅                 │
│  🎨 文化历史    🌊 水上活动                  │
│  🎢 主题乐园    🛍️ 购物                     │
│  🌿 自然风光    🎭 演出娱乐                  │
└────────────────────────────────────────────┘
```

**设计逻辑**：
- 用户不需要输入目的地 → 先选兴趣类型 → 再根据地理位置推荐
- 每个兴趣卡片有高质量配图 + 简短文案
- 点击进入二级页面：按子类别 + 目的地双维度筛选

**HearHere 可借鉴**：
- 首页增加"按旅行风格探索"模块（如：🏔️ 自然放松、🍜 美食之旅、📸 拍照打卡、🏛️ 文化深度、👨‍👩‍👧 亲子出游）
- 不依赖语音输入，为"没想好去哪"的用户提供入口
- 点击某个风格后进入推荐流，类似现有 discover 页面但用风格替代目的地

### 1.2 餐厅推荐三维分类系统

TripAdvisor 的餐厅推荐有三个维度的划分，极其精细：

#### 维度一：场所类别（Venue Type）
```
餐厅 | 咖啡和茶 | 甜品 | 酒吧 | 快餐 | 面包房
```

#### 维度二：餐点类型（Meal Type）
```
早餐 | 早午餐 | 午餐 | 晚餐 | 下午茶 | 宵夜
```

#### 维度三：菜式（Cuisine）
```
中餐 | 日料 | 意大利菜 | 法餐 | 海鲜 | 川菜 | 粤菜 | 素食 | 烧烤 | ...
```

**交互方式**：
- 三个维度是**级联筛选**而非并列——先选场所类别，再选餐点类型，最后选菜式
- 每个筛选项显示该条件下的**餐厅数量**
- 筛选结果按 "旅行者评分" 排序（默认），可切换为距离/价格
- 每个餐厅卡片显示：照片、评分、菜式标签、价格等级（$-$$$$）、点评数

**HearHere 可借鉴**：
- 美食推荐页引入至少两个维度：
  - 餐点类型：早餐/午餐/晚餐/下午茶/宵夜（与行程时间绑定）
  - 菜式/口味：本地特色/海鲜/火锅/素食/小吃/甜品（与用户偏好绑定）
- 餐厅卡片增加：人均价格范围、评分来源（高德/大众点评）、招牌菜
- 与行程时间联动：Day 1 午餐推荐什么 → Day 1 晚餐推荐什么

### 1.3 评价系统

TripAdvisor 的核心壁垒是 **10 亿+ 真实用户点评**：
- 评分气泡（1-5 分）+ 文字点评
- "旅行者之选"徽章（年度最佳）
- 评价分类标签（"适合家庭""浪漫""性价比高"等）
- "旅行者照片"板块——比官方图更真实

**HearHere 可借鉴**：
- 高德 POI 本身有评分和评价数，可以用这些数据
- LLM 生成的推荐语可以结合高德评分作为"可信度标识"
- 卡片上显示评分星 + "XX 条评价"增加可信度

## 二、Trip.com / TripGenie（携程 AI）

### 2.1 首页个性化

Trip.com 首页是典型的 OTA 模式，但有很多值得借鉴：

```
┌──────────────────────────────────┐
│  🔍 搜索栏（目的地/酒店/机票）        │
├──────────────────────────────────┤
│  📍 热门目的地（滚动卡片）            │
│  🏷️ 旅行灵感（瀑布流推荐文章）        │
├──────────────────────────────────┤
│  💬 TripGenie AI 助手入口          │
│  "想去哪里？告诉我，帮你规划"          │
├──────────────────────────────────┤
│  🎯 个性化推荐（基于浏览历史）         │
│  🔥 限时优惠 / 热门活动              │
└──────────────────────────────────┘
```

### 2.2 TripGenie 对话式交互

TripGenie 是携程的 AI 助手，内嵌在 App 中：
- **对话式输入**：用户用自然语言描述需求
- **结构化卡片输出**：AI 返回的不是纯文本，而是可交互的酒店/机票/景点卡片
- **多轮对话**：可以追问"便宜一点的""离海边近的"
- **一键预订**：AI 推荐的酒店/机票可以直接跳转预订

**HearHere 可借鉴**：
- TripGenie 的"对话 → 结构化卡片"模式与 HearHere 的"语音 → 标签 → 卡片"高度一致
- 他们的亮点是**卡片可操作**（点击预订），HearHere 的亮点应该是**卡片可选择**（+/- 加入行程）
- TripGenie 的"便宜一点""近一点"追问模式 → HearHere 可以加入"调整偏好"入口（在 discover 页面快速修改标签）

## 三、Wanderlog（结构化行程规划）

### 3.1 核心 UX 模式

Wanderlog 是行程规划的标杆产品：

```
┌─────────────────────────────────────────┐
│  Day 1                    [+ 添加地点]    │
│  ┌─────────────────────────────────────┐ │
│  │ 09:00  普济寺                        │ │
│  │        📍 位于普陀山中心              │ │
│  │        ⏱ 2小时  💰 ¥35             │ │
│  │        📝 上午人少，适合慢慢游览        │ │
│  │        🚶 步行15分钟 → 下一站         │ │
│  ├─────────────────────────────────────┤ │
│  │ 12:00  普济寺素斋                     │ │
│  │        🍜 素面、素鸭                  │ │
│  │        ...                          │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │ Day 2                    [+ 添加地点] │ │
│  │ ...                                 │ │
│  └─────────────────────────────────────┘ │
│                                          │
│  💰 总预算: ¥1,200/人                     │
│  📏 总距离: 15km                         │
└─────────────────────────────────────────┘
```

**亮点功能**：

| 功能 | 描述 | HearHere 参考 |
|------|------|-------------|
| **拖拽排序** | 行程项可以拖拽调整顺序 | 攻略生成后允许手动调序 |
| **协作编辑** | 分享链接给同行人一起编辑 | 攻略分享链接（P2 需求） |
| **自动优化路线** | 根据地点距离自动排序当天的行进路线，避免走回头路 | 🔴 **高优先级**——现在攻略没有路线优化 |
| **费用追踪** | 自动累加每项费用，显示总预算 | 攻略生成时已有 cost 字段，加个合计 |
| **地图标注** | 所有地点在一张地图上编号标注 | 已有地图，可加编号连线 |
| **笔记/备注** | 每个地点可添加私人笔记 | 简单 |

### 3.2 "没想好去哪"的入口

Wanderlog 首页有三种进入方式：
1. **新建空白行程**（完全自由）
2. **从模板开始**（"东京3日游""巴厘岛蜜月"等）
3. **AI 帮我规划**（输入目的地+天数 → AI 生成）

**HearHere 可借鉴**：
- 首页增加"旅行灵感/模板"——不是完整攻略，而是几组精选目的地+风格的简短组合
- "不知道去哪？试试这些"——降低冷启动门槛

## 四、Wanderboat（多模态 AI 旅行）

### 4.1 多模态输入

Wanderboat 最大的亮点是**不只是文字输入**：

| 输入方式 | 示例 |
|----------|------|
| 📝 文字 | "带父母去京都3天，喜欢寺庙和美食" |
| 📷 图片 | 上传一张风景照 → AI 识别地点并推荐周边 |
| 📎 PDF/链接 | 粘贴一篇小红书攻略链接 → AI 提取关键地点并生成行程 |
| 🎤 语音 | 口语描述需求 |

### 4.2 交互 UX

- 左侧：地图（POI 标注）
- 右侧：对话区 + 行程卡片
- 对话过程中地图实时更新标注
- 点击地图上的 POI → 弹出详情 + "加入行程"按钮

**HearHere 可借鉴**：
- 📷 **图片灵感输入**：用户拍一张别人分享的旅行照片，AI 识别地点并推荐类似风格的景点
- 📎 **攻略链接解析**：粘贴马蜂窝/小红书攻略链接 → 提取其中的景点/餐厅 → 一键导入候选
- 这两个功能是**差异化杀手锏**——目前国内旅行产品几乎没有

## 五、Layla (Roam Around)（社交+对话式）

### 5.1 对话式规划

Layla 的交互是纯对话式的（类似 ChatGPT）：
- "我想去一个温暖的地方，有海滩，不要太商业化"
- AI 回复："巴厘岛的仓古可能适合你——它比库塔安静，有黑色沙滩和稻田..."
- 用户："听起来不错，帮我规划 4 天"
- AI → 生成 4 天行程卡片

### 5.2 社交分享

Layla 的独特之处是**行程分享格式**：
- 生成的行程可以一键分享到 Instagram/TikTok
- 分享格式经过设计：精美的行程卡片图 + 配乐 + 文字
- 这带来了大量的自然流量

### 5.3 "不知道去哪"模式

Layla 有一个**灵感发现**页面：
- "周末逃离"、"蜜月圣地"、"背包客天堂"等主题集合
- 每个集合是 AI 精选的目的地卡片
- 点击进入对话式规划

**HearHere 可借鉴**：
- 🎨 **行程分享卡片**：攻略完成后生成精美分享图（已有部分实现）
- 🧭 **灵感发现**：主题集合替代搜索（"周末两日游""陪父母好去处""闺蜜打卡地"）
- 分享格式设计要适合微信/朋友圈/小红书

## 六、Mindtrip（实时调整）

### 6.1 核心交互

Mindtrip 的定位是"AI 旅行伴侣"而非单次规划工具：
- 生成行程后，**可以在旅途中实时调整**
- "下雨了，帮我把第三天的户外活动换成室内的"
- "这家餐厅排队太长，附近有什么替代？"

### 6.2 多源数据整合

Mindtrip 整合多个数据源：
- 地图 POI（Google Maps）
- 社交媒体（Instagram/TikTok 热门地点）
- 天气数据
- 营业时间/实时排队

**HearHere 可借鉴**：
- 🔄 **旅途中的实时调整**：这是 P2 需求（"语音实时修改"），但 Mindship 证明了这个价值
- 🌦️ **天气感知**：生成攻略时结合天气预报调整推荐（下雨天自动替换室内活动）
- ⏰ **营业时间感知**：搜索 POI 时检查营业时间，避免推荐已关门的地点

## 七、通用 UX 模式总结

### 7.1 用户不需要明确目的地时的入口设计

| 产品 | "没想好去哪"入口 |
|------|----------------|
| TripAdvisor | "按兴趣查找" 热门分类卡片 |
| Trip.com | 旅行灵感瀑布流 + 热门目的地 |
| Wanderlog | 旅行模板 + AI 生成 |
| Layla | 灵感发现 → 主题集合卡片 |
| **HearHere 现在** | ❌ 无——必须输入目的地 |

**建议**：HearHere 首页增加"旅行风格探索"入口（见下方具体方案）

### 7.2 推荐系统分类模式

| 产品 | 分类维度 |
|------|---------|
| TripAdvisor | 兴趣类型（户外/美食/文化...）→ 子分类 → 评分排序 |
| Trip.com | 目的地 → 住宿/景点/美食 → 价格/距离排序 |
| Wanderlog | 手动自由分类 |
| **HearHere 现在** | 景点/美食/伴手礼/酒店（Tab 切换） |

### 7.3 AI 交互模式

| 模式 | 代表产品 | 适用场景 |
|------|---------|---------|
| 对话→结构化 | TripGenie, Layla | 有大致方向但需要 AI 细化 |
| 选择→生成 | Wanderlog AI, Mindtrip | 明确需求，要快速出结果 |
| 浏览→发现 | TripAdvisor, Layla | 没有方向，需要灵感 |
| 多模态→提取 | Wanderboat | 看到别人分享，想复刻 |

**HearHere 目前只有"选择→生成"和"对话→结构化"（语音输入），缺少"浏览→发现"。**

## 十、HearHere 设计建议（带优先级）

### 🔴 P0 — 差异化核心能力

#### 1. 首页「兴趣发现」入口（参考 TripAdvisor + Layla）

```
新增模块：首页语音输入框下方 → "不知道去哪？按你的兴趣探索"
├── 兴趣卡片网格（3x2 或横向滚动）
│   ├── 🏛️ 人文历史 → 推荐故宫、莫高窟、平遥古城...
│   ├── 🌊 看海发呆 → 推荐东山岛、嵊泗、南澳岛...
│   ├── 🍜 吃遍美食 → 推荐成都、顺德、潮汕...
│   ├── ⛰️ 徒步爬山 → 推荐虎跳峡、武功山、四姑娘山...
│   ├── 📸 拍照打卡 → 推荐阿那亚、松阳、霞浦...
│   └── ✨ 随缘推荐 (Surprise Me)
└── 每个卡片点击进入 → 携带兴趣标签 → 语音/文字补充细节 → 生成攻略
```

#### 2. 餐厅三级分类体系（参考 TripAdvisor）

```
美食推荐页改造：
├── 第一级 Chip：餐厅类型
│   └── 精致正餐 | 小吃快餐 | 咖啡馆 | 甜品店 | 夜市排档 | 素食
├── 第二级 Chip：用餐时段
```

## 十一、HearHere 的独特优势（不要丢失！）

与以上所有竞品相比，HearHere 独有的杀手锏：

| 竞品没有的 | HearHere 已有的 |
|-----------|---------------|
| ❌ 没有语音交互 | ✅ 语音输入 + ASR + 呼吸按钮 |
| ❌ 英文为主 | ✅ 纯中文，为中国用户设计 |
| ❌ 无高德地图数据 | ✅ 对接高德真实 POI + 坐标 |
| ❌ 无标签化需求提取 | ✅ 语音 → 标签提取 → 确认 |
| ❌ 推荐语不个性化 | ✅ LLM 生成个性化推荐语 |

**核心策略：在竞品最强的能力上学习追赶，在竞品缺失的语音 + 中文 + 真实数据上建立护城河。**
