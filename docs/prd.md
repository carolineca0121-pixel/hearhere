产品需求文档 (PRD): HearHere / 听见
1. 产品定义
HearHere / 听见 是一款基于语音交互的定制化旅行智能助手。它通过“听懂”用户琐碎、混乱的需求，将其转化为结构化的旅行计划，并利用 AI 解决多人出行的冲突，同时提供富有氛围感的目的地体验（歌单、情感瞬间建议）。
品牌口号：在这里听见你的需求。
目标用户： NF 型人格（追求氛围感）、多人出行组织者（解决冲突）、懒人旅行者。
2. 核心逻辑流程 (The HearHere Loop)
倾听 (Hear): 用户通过类似 Typeless 的语音入口，说出原始、无逻辑的旅行愿望。
理解 (Process): 系统提取关键信息：时间、地点、预算、人员偏好（A爱吃辣，B要看海）、硬性约束（老人不能多走）。
对齐 (Align): 自动识别多人需求的冲突点，生成“最大公约数”方案。
探索 (Here): 针对模糊需求（如“想看落日”），通过 AI 搜索社交媒体，提供 Top 10 真实评价卡片供用户滑动选择。
呈现 (Vibe): 生成完整行程，并附带目的地专属氛围歌单与“情感高光时刻”提示。
3. 功能模块详细说明
3.1 Typeless 式语音交互技能 (The Voice Skill)
技术实现: 集成本地 Whisper (ASR) + Ollama (NLU)，仅简体中文。
交互细节:
首页仅有一个呼吸感波动按钮。
录音结束后，系统不只是转文字，而是展示**“我听到了这些关键点”**的标签云。
用户可以手动点击标签微调，或继续语音补充。
3.2 冲突协调引擎 (Harmony Engine)
多维度处理: 当用户提到“三个人去”时，AI 自动开启“家庭/团体模式”。
方案决策: 如果需求冲突（如：A要逛街，B要爬山），AI 会寻找带有商圈的公园，或在时间线上进行交替排期。
3.3 实时情报库 (Insight Hub)
数据来源: MVP 使用 Mock 数据或本地 Python 爬虫；模拟小红书、大众点评类真实评价，不接第三方搜索 API。
交互方式: Tinder 样式的卡片，用户左滑舍弃，右滑加入行程。每张卡片必须包含：一张美图、一条犀利的真实评价、一个推荐理由。
3.4 情感与氛围感 (The Vibe Moment)
视觉映射: 界面主题颜色随目的地实时变化（例如：去青海湖是天蓝色，去故宫是朱砂红）。
High Moment: 在行程中自动插入“情感锚点”。例如：“19:00 晚宴结束后，建议去天台，此时最适合告白/求婚，背景音乐建议播放《XXX》”。
视觉辅助歌单: 提供与目的地气质契合的歌单封面作为视觉参考（V1 不实现真实播放）。
4. 技术栈要求
Frontend: Next.js 14+ (App Router), Tailwind CSS.
UI Components: Shadcn UI, Framer Motion (用于实现呼吸感和卡片滑动).
Authentication: NextAuth.js (Credentials Provider，注册即创建本地 User).
Database: SQLite + Prisma (存储用户行程、偏好).
AI/LLM: 本地 Ollama；ASR: 本地 Whisper 服务.
情报: Mock JSON 或本地 Python 爬虫（Insight Hub）.
语言: 仅简体中文。V1 不展示地图。
5. UI/UX 风格指南
极简主义: 拒绝繁琐的输入框，以大面积留白和圆润的卡片为主。
通透感: 采用 Glassmorphism (毛玻璃) 效果，背景为流动的彩色渐变。
动效: 语音波动效果、卡片滑动的物理感。
